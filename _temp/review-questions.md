# Project-Spec-build.md 疑问点清单

## Q1
- **行号**：L3
- **原文摘录**："确保本项目仓库具备一套符合下述规范的 **Agent 规约**"
- **疑问描述**：全文未给出"Agent 规约"的显式定义；"规约"与"规约体系"两个表述在文中交替使用（如 L38 "规约体系"、L185 "规约总纲"），两者是否等同、边界如何，读起来存在两种理解。

## Q2
- **行号**：L12 与 L272–L280
- **原文摘录**：L12 "多 Agent 协作能力检测：检测当前环境是否支持多 Agent 协作（子 Agent 派发 / Worker / Task Delegation 等）"；L275–L280 "③ 环境能力检测方法：……若检测失败，自动降级为模式 C"
- **疑问描述**：L12 要求在"权限与能力确认"阶段完成检测，L275–L280 的检测方法属于建成后 `docs/agent-execution-mode.md` 的内容；构建期应由谁、在哪一步执行该检测，两处表述的适用时机存在两种理解。

## Q3
- **行号**：L20
- **原文摘录**："你必须完成以下评估并输出决策报告"
- **疑问描述**："以下评估"指代的具体步骤集合未在 L20 当句列明，需结合 L359 "现状扫描 → 模式判定 → 协作检测 → 决策报告"才能还原；"以下"的指代范围存在歧义。

## Q4
- **行号**：L38 与 L40
- **原文摘录**：L38 "不存在 `AGENTS.md`，不存在 `docs/` 目录，无有效规约体系"；L40 "已有一定规模的规约文档，但结构/格式/索引不符合本规范"
- **疑问描述**：A 情况三个条件之间是"且"还是存在例外（如有 README.md 但无 AGENTS.md 和 docs/ 时应归 A 还是 B）；C 情况中"一定规模"未给出量化边界，A/C 与 B 的划分界限存在两种理解。

## Q5
- **行号**：L41 与 L67
- **原文摘录**：L41 "已有完整规约且基本符合规范，仅存在小问题"；L67 "若判定为情况 D（仅校验修正），报告后直接进入第五节校验流程，无需大动"
