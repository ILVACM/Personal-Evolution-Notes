## 一、问题诊断（根因表）

模板实际使用暴露出扫描不彻底的典型症状（每条对应一个 weakness 根因）：
- 遗漏非标准目录（infra/、scripts/、.config/）→ 未要求穷举遍历，依赖启发式猜测
- 跳过隐藏目录/文件（.github/、.vscode/、.env.example）→ 未要求包含 dotfiles/dotdirs
- 未识别非 Markdown 规约文档（YAML/TOML/JSON、Makefile、Dockerfile）→ 扫描范围过窄
- 深层嵌套被截断（>3-4 层停止）→ 未设递归深度要求
- 符号链接/monorepo 子项目未跟随 → 未要求处理特殊文件系统结构
- 扫描结果无完整性证明 → 缺扫描完成标准与校验机制
- 大仓库扫描因上下文溢出中断未续扫 → 缺分片扫描和断点续传

## 二、修改目标规格（新增/强制项）

### 2.1 全量扫描协议（新增独立章节或在现有扫描章节显著强化）

**2.1.1 扫描范围定义（穷举式）**——以下扫描不得以"未发现相关内容"为由跳过任一：
| 扫描类别 | 要求 |
|----------|------|
| 目录遍历 | 从仓库根开始递归遍历所有目录，无深度限制；显式包含 dotfiles/dotdirs（.github/、.vscode/、.config/ 等） |
| 文件类型 | 不仅 .md；必覆盖 .yaml、.yml、.toml、.json、.env*、Makefile、Dockerfile*、docker-compose*、*.sh、*.py、*.ts、*.js、*.go、*.rs 等实际存在文件类型 |
| 符号链接 | 必须跟随并记录目标路径 |
| Monorepo | 检测到多 package.json / go.mod / Cargo.toml / pyproject.toml 时，每个子项目独立扫描单元 |
| 排除项 | 仅排除明确构建产物目录（node_modules/、dist/、build/、.git/、__pycache__/、vendor/），排除列表必须显式列出 |

**2.1.2 扫描执行策略**：
- 分片扫描：文件数 > 500 或目录深度 > 8 时，必须按顶层目录分片，每片独立扫描后合并
- 断点续传：中断必须记录已完成分片，下次从断点继续，不得重头开始
- 并行安全：多 Agent 协作时每 Agent 负责明确分片，避免重复或遗漏
- 扫描工具：优先用文件系统 API / MCP 工具程序化遍历，禁止仅靠 LLM"回忆/猜测"

**2.1.3 扫描产出物（强制生成清单文件，如 `_temp/scan-manifest.md`）**，内容含：扫描时间/仓库根路径/总文件数/总目录数/最大目录深度/排除目录列表/符号链接列表(<源→目标>)/monorepo 子项目列表/分片信息(分片数、各片文件数、完成状态)；**目录树（完整，不得截断）**；**文件分类统计表**(类型|数量|示例路径)；**潜在规约文档候选**(路径+判定理由)。

**2.1.4 扫描完整性校验（强制自检，任一失败则扫描未完成、不得进入后续）**：
| 校验项 | 方法 | 通过标准 |
|--------|------|---------|
| 覆盖率 | 文件系统工具重新计数 vs 清单计数 | 误差=0 |
| 深度 | 目录树最深路径 vs 报告 | 一致 |
| 排除项 | 确认排除目录未出现在结果 | 无泄漏 |
| 文件类型 | 随机抽样 5% 验证分类 | 错误率<1% |
| 分片完整性 | 所有分片 completed | 无 pending/failed |

结果附加清单末尾：`### 扫描完整性校验` 表 + `**扫描状态：COMPLETE / INCOMPLETE**`。仅 COMPLETE 方可进入分析阶段。

### 2.2 全量分析协议（在现有分析章节强化）

- **分析输入**：必须为扫描清单标记"潜在规约文档候选"的全部文件，不得自行筛选子集。
- **分析深度**：对每候选文件提取并记录 7 项
  | 提取项 | 说明 |
  |--------|------|
  | 文件路径 | 相对路径 |
  | 文件类型 | md / yaml / toml / json / code / other |
  | 规约相关性 | 高 / 中 / 低 / 无关 |
  | 内容摘要 | ≤200 字概括规约相关内容 |
  | 归属层级预判 | 约束层 / 知识层 / 实例层 / 待讨论 |
  | 与现有体系关系 | 新增 / 补充 / 冲突 / 冗余 |
  | 可信度标签 | verified / inferred / assumed / conflicting / stale（沿用 v2.0 五级标签） |
- **分析产出物** `_temp/analysis-report.md`：候选文件提取项表格 + 按层级分组汇总 + 冲突/冗余项清单 + 分析完整性声明"本报告覆盖了扫描清单中全部 N 个候选文件，无遗漏"。
