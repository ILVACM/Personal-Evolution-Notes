## 四、审查要点④：条件分支互斥性、穷尽性与阈值明确性

**❌不明确 | L280 『- 若检测失败，自动降级为模式 C』**
- 问题描述：该降级规则未限定适用前提，与模式定义自相矛盾。检测失败意味着环境不支持多 Agent：若原判定为模式 A（单 Agent 直接执行，本就不依赖多 Agent），强制「降级为模式 C」反而错误升级（模式 C 的适用条件是「任务本身复杂度较高」）；若原判定为模式 D，降级目标亦未指明。规则字面执行会产生错误行为。
- 修改建议：将第280行『若检测失败，自动降级为模式 C』改为『若原判定为模式 B 或模式 D 且检测失败，自动降级为模式 C；若原判定为模式 A，维持模式 A』。

**⚠️有歧义 | L141 `### 模式 A：多 Agent 协作（优先）`、L166 `### 模式 B：单 Agent（降级）` 与 L261–L264 模式 A–D 表**
- 问题描述：同一提示词内「模式 A」「模式 B」存在含义相反的复用——第二节「模式 A=多 Agent 协作、模式 B=单 Agent」，而 4.3.1 要求写入交付文档的模式表中「模式 A=单 Agent 直接执行、模式 B=多 Agent 协作执行」。虽然 L139 区分了「构建期」与「运行期」两个作用域，但脱离章节上下文引用「模式 A」时指向不唯一，Writer Agent 在撰写 AGENTS.md 协作规范板块时极易串用。
- 修改建议：将第141行『### 模式 A：多 Agent 协作（优先）』改为『### 2.1 构建协作模式：多 Agent 协作（优先）』；将第166行『### 模式 B：单 Agent（降级）』改为『### 2.2 构建协作模式：单 Agent（降级）』；并将第175行『无论哪种模式』改为『无论哪种构建协作模式』。

**⚠️有歧义 | L32 `### 0.2 执行模式判定`、L351 『- 执行模式：多Agent协作 / 单Agent降级』 与 4.3.1 的「运行方式/模式 A–D」**
- 问题描述：「执行模式」一词承担三种含义：0.2 的仓库现状分类（情况 A–D）、L351 的协作方式（多/单 Agent）、4.3.1 的运行期模式（A–D）。三处共用同一术语且各自独立使用 A–D 字母，读者无法仅凭术语确定所指。
- 修改建议：将第32行『### 0.2 执行模式判定』改为『### 0.2 现状分类判定（情况 A/B/C/D）』；将第351行『- 执行模式：多Agent协作 / 单Agent降级』改为『- 协作模式：多Agent协作 / 单Agent降级』；「执行模式/运行方式」专留给 4.3.1 语境。同时建议将第359行『模式判定』随改为『现状分类判定』。

**⚠️有歧义 | L284 『- 模式 B → 模式 C 的降级条件与切换流程』**
- 问题描述：降级策略仅覆盖 B→C 一条路径，不穷尽：模式 D（混合模式）依赖部分协作能力，检测失败或部分能力缺失时的降级路径未定义；L297 输出模板『降级情况：无 / 已从 B 降级至 C』同样只枚举一种降级。
- 修改建议：将第284行『模式 B → 模式 C 的降级条件与切换流程』改为『模式 B → 模式 C、模式 D → 模式 C（或模式 A）的降级条件与切换流程』；并将第297行『降级情况：无 / 已从 B 降级至 C』改为『降级情况：无 / 已从 B 降级至 C / 已从 D 降级至 C 或 A』。

**⚠️有歧义 | L261–L264 模式适用条件（『任务范围小』『任务复杂』『环境仅支持有限协作』等）**
