> 本文件是「重构项目规约体系构建提示词模板」任务的唯一需求基准，供 Agent-A/B/C/D/E 各角色读取。
> 被修改对象：`d:\Personal-PitFall-Log\prompts\Project-Spec-build.md`（提示词模板，即"生产规约体系的模具"）。

## 〇、全局约束

- 最终交付物是**修改后的提示词模板文件**，而非直接生成规约体系文件。修改的是"模具"，不是"铸件"。
- **禁止创建 `docs/`、`knowledge/` 等目录和文件**。
- 保留原模板中仍然适用的风格和措辞习惯，仅在逻辑/结构/内容层面修改。
- 原模板中与目标设计不矛盾但目标设计未涉及的额外内容，予以保留。
- 修改后的模板必须**自包含**：任何 Agent 拿到该模板后，无需额外上下文即可执行并生成完整的三层规约体系。
- 模板中所有路径引用使用**相对路径**。
- 模板中涉及文件内容的示例，使用代码块包裹并标注语言类型（yaml / markdown / text）。
- 所有输出使用简体中文。

## 一、目标设计规格（完整，逐字执行依据）

### 1.1 体系总览

```text
AGENTS.md（总纲 · 唯一第一入口 · 最高权威）
    │
    ├──► docs/（约束层）
    │       ├ INDEX.md
    │       └ 规约细则...
    │
    ├──► knowledge/（知识层 + 实例注册）
    │       ├ INDEX.md（知识层总索引）
    │       ├ Instances-INDEX.md（实例层注册表）
    │       └ 通用规范文档...
    │
    └──► 实例文档（散布于项目各自然归属位置）
```

### 1.2 三层定义

**约束层（`docs/`）**
- 定位：Agent 行为规则的唯一权威来源
- 内容：编码规范、架构约定、工作流约束、多 Agent 协作规范、运行方式判定标准、全局校验机制
- 性质：规定性（Prescriptive）
- 约束力：`[约束]`——违反即为执行错误
- 变更频率：低
- 维护者：规约管理者（人）
- 路由职责：INDEX.md 作为约束层总路由，向下仅给出知识层入口指针，不列知识层或实例层明细

**知识层（`knowledge/` 中的规范文档）**
- 定位：通用规范与参考知识的集合，是实例层的"模具"
- 内容：环境规范（服务器参数、网络约束等）、技术选型指南、通用部署规范、安全基线、性能标准等
- 性质：描述性（Descriptive）
- 约束力：`[参考]`——Agent 应当遵守；与约束层冲突时以约束层为准
- 变更频率：中
- 维护者：领域负责人（人）
- 路由职责：INDEX.md 按领域分类，每条规范标注其下游实例清单（含物理路径）

**实例层（散布于项目各处的执行文档）**
- 定位：具体项目的执行文档，是知识层规范的"铸件"
- 内容：具体部署文档、配置说明、实施方案、特定项目 README 等
- 性质：执行性（Operational）——自包含的完整操作指令
- 约束力：`[自包含指令]`——文档本身即为完整执行依据
- 变更频率：高
- 维护者：项目实施者（人或 Agent）
- 物理位置：不集中存放，置于项目自然归属位置
- 身份判定：文档头部元信息区包含 `governance: instance` 字段
- 注册方式：在 `knowledge/Instances-INDEX.md` 中登记路径与继承关系

### 1.3 路由设计

路由链路：

```text
AGENTS.md（总纲）
    ├──► docs/INDEX.md ──► 约束层细则
    │       └── 指针：knowledge/INDEX.md
    └──► knowledge/INDEX.md ──► 通用规范
            ├── 每条规范的下游实例清单
            └──► Instances-INDEX.md ──► 实例文档物理路径
                                          └──► 元信息区 inherits_from → 回溯知识层
```

**约束力层级：** AGENTS.md ＞ docs/ ＞ knowledge/ ＞ 实例文档。冲突时上层覆盖下层。

各索引文件职责：

| 文件 | 职责 |
|------|------|
| `docs/INDEX.md` | 约束层总路由 + 下层入口指针 |
| `knowledge/INDEX.md` | 知识层总索引，按领域列出通用规范，每条标注下游实例 |
| `knowledge/Instances-INDEX.md` | 实例层注册表，列出所有实例文档物理路径、所属项目、继承规范、状态 |

### 1.4 继承与扩展规则（知识层 → 实例层）

| 规则 | 说明 |
|------|------|
| 只能继承和扩展 | 实例文档必须包含所继承知识层规范的所有相关约束 |
| 不能覆写或矛盾 | 不得出现与所继承知识层规范相矛盾的表述 |
| 偏离需豁免 | 先在知识层新增豁免条款（编号），实例在 `overrides` 字段引用 |
| 自包含原则 | 正文中不得出现"详见知识层 XX"等跳转指令，所有信息在文档内完整呈现 |
| 元信息与正文分离 | 继承来源等置于文档头部声明区，执行时仅阅读正文 |

实例文档元信息区模板：

```yaml
---
title: <文档标题>
version: <版本号>
last_updated: <日期>
governance: instance
inherits_from:
  - knowledge/<规范文件名>.md
overrides: none | <豁免条款编号>
status: active | deprecated
---
```

### 1.5 管辖范围边界

| 属于规约体系管辖 | 不属于规约体系管辖 |
|------------------|-------------------|
| AGENTS.md | 项目源代码 |
| `docs/` 下所有规约文件 | 构建产物（dist/、build/） |
| `knowledge/` 下所有通用规范文档 | 运行时数据、日志 |
| `knowledge/Instances-INDEX.md` | 第三方依赖源码 |
| 所有携带 `governance: instance` 标识的文档 | 临时文件、草稿、未注册文档 |

### 1.6 维护规则

维护职责：

| 层级 | 维护者 | 变更触发条件 | 影响范围 |
|------|--------|-------------|---------|
| 约束层 | 规约管理者（人） | 流程/规则变更 | 全局 |
| 知识层 | 领域负责人（人） | 通用规范/环境标准变更 | 所有继承该规范的实例 |
| 实例层 | 项目实施者 | 项目迭代 | 仅当前实例文档 |

实例文档生命周期操作：

| 场景 | 必须动作 |
|------|---------|
| 新增 | ① 写入元信息区；② Instances-INDEX.md 新增一行；③ 知识层下游清单同步 |
| 移动 | ① 更新 Instances-INDEX.md 路径；② 更新知识层下游清单路径 |
| 删除 | ① Instances-INDEX.md 移除；② 知识层下游清单移除；③ 确认无引用 |
| 知识层更新 | 通过 inherits_from 反向定位所有受影响实例，逐一校验 |
| 路径失效 | 标注 `[路径失效]`，报告 Orchestrator，不自行猜测 |

身份判定规则：
- 任何 Markdown 文档头部含 `governance: instance` 即视为实例层管辖
- Agent 遇到此类文档应通过 Instances-INDEX.md 确认注册状态
- 未注册但携带标识的文档，Agent 应报告注册缺失

### 1.7 核心设计原则

| 原则 | 体现 |
|------|------|
| 唯一入口 | Agent 一切路由从 AGENTS.md 开始 |
| 规定与描述分离 | 约束层管"怎么做"，知识层管"是什么" |
| 模具与铸件分离 | 知识层是通用规范，实例层是具体实现 |
| 实例自包含 | 实例文档正文独立可用 |
| 物理位置自由，逻辑注册统一 | 实例文档放自然位置，通过 Instances-INDEX.md 统一注册 |
| 上层覆盖下层 | 约束力严格按层级 |
| 低层变更不污染高层 | 实例层高频变更不影响约束层 |

## 三、特别注意事项

- 模板中所有路径引用使用相对路径。
- 模板中涉及文件内容的示例，使用代码块包裹，并标注语言类型（yaml / markdown / text）。
- 模板中应明确说明：实例文档**不集中存放**，`knowledge/` 目录下**仅有** INDEX.md、Instances-INDEX.md 和通用规范文档，不存放实例文档本体。
- 模板中应明确说明：`instances/` 目录**不存在**，实例注册表为 `knowledge/Instances-INDEX.md`。
- 模板应指导 Agent 在生成 AGENTS.md 时写入完整的路由声明和约束力层级。
- 模板应指导 Agent 为每个生成的文件标注其属于哪一层。
- 模板中应包含明确的执行步骤（Step 1, Step 2, ...），引导 Agent 按序生成规约体系各文件。
- 模板中应包含校验清单（Checklist），供 Agent 在生成完成后自查。
